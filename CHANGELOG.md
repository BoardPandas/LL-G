## [Unreleased]

### Fixed
- **`kb/bash/llms.txt` had 24 CRs written straight into the blob**, turning CI red, because `.gitattributes` only governs what a git CLIENT commits -- a GitHub contents-API write stores the bytes it is sent verbatim, with no clean filter in the path. Stripped, and the gap is now recorded in `kb/git/crlf-expansion-doubles-file.md`: normalize inside whatever tool performs the API write, because the repo's own rules do not apply there.
- **`scripts/check-kb.mjs` only inspected `llms.txt` files for CRs, never entry files** -- where almost all the content lives -- so a CR in an entry passed clean. Caught by writing one into this very lesson while drafting it. Entry files are now checked, asserted in the blocking direction.
- **The master index was doubling in size every few commits, and `.gitattributes` now stops it.** A Windows write turned `llms.txt` into CRLF (one CR per line); a later tool treating a lone CR as a line terminator rewrote it with LF only, and every CR became a real blank line. Measured across the history: 257 -> 768 -> 1537 -> 3071 lines while actual content stayed at ~173, so the file reached 2,898 blank lines against 173 of content, and "update one entry count" landed as a 768-insertion/257-deletion diff that made blame on the index useless. `* text=auto eol=lf` pins the checkout so a clone with `core.autocrlf=true` cannot reintroduce the CRs; the accumulated blank runs were collapsed in `llms.txt`, `kb/go/`, `kb/postgres/` and `kb/windows/`, and every file carrying mixed endings was normalized (17 of them, including two entries that landed upstream mid-fix from a Windows machine -- the bug in the act). Note CRs must be *deleted*, not translated to newlines -- translating them re-creates the expansion.
- **Two complete lessons were invisible.** `kb/better-auth/databasehooks-only-supports-core-models.md` and `kb/rust/ll-hook-swallow-blind-spots.md` were well-formed MEDIUM entries that no `llms.txt` listed, so nothing routing through the index could ever read them. Both are now indexed.
- **Three HIGH entries recorded severity as prose**, so "load all HIGH-severity entries" skipped exactly the entries it most needed: `kb/cmd/mid-path-wildcards.md`, `kb/graph-api/oauth2grants-need-delegated-permission-grant.md` and `kb/typescript/ts6-peer-dep-conflict.md` now carry real YAML frontmatter.
- Corrected the Tailwind CSS entry count in the master index (claimed 10, folder has 9).

### Added
- New Git gotcha (HIGH): **a CRLF checkout plus an LF-only rewrite turns every CR into a blank line, and the file doubles every cycle.** `core.autocrlf=true` writes CRLF, then a tool treating a lone CR as a line terminator rewrites with LF and emits one line per CR, so the new line count is exactly old lines plus old CRs. Written up from this repo's own master index, which went 257 -> 768 -> 1537 -> 3071 lines while its content stayed at ~173. Records the two non-obvious halves: `eol=lf` (not just `text=auto`) is what pins the checkout, and repair must DELETE the CRs because translating them to newlines performs another cycle by hand.
- **CI that actually fails on a broken knowledge base** (`.github/workflows/ci.yml` + `package.json`). The repo had no CI at all, so `scripts/check-index-counts.mjs` never ran and the drift it exists to catch accumulated unnoticed. `npm run check` now runs both guards on every push and PR, and both were negative-tested in the blocking direction (orphan, prose severity, CR bloat, count drift all exit 1).
- **`scripts/check-kb.mjs`**, a structural guard for the four ways a lesson can exist and never load: an entry no `llms.txt` lists, severity written as prose instead of YAML, a `tech:` key that disagrees with its folder, and CR-expansion blank bloat. It also budgets the master index by BYTES (20 KB ceiling) rather than lines, because a line budget keeps passing while single lines grow to thousands of characters -- the failure this repo already documents in `kb/claude-code/line-budgets-gamed-by-long-lines.md` and had nonetheless done to its own index.
- Three new gotchas from the 2026-09-02 Jonas workstation-ID work: NinjaOne `/v2/activities` `lastActivityId` is the newest id in the tenant, not a page cursor (HIGH); NinjaOne custom field definitions are UI-only, `POST /v2/device-custom-fields` returns 405 (MEDIUM); a PowerShell function returning an `Invoke-RestMethod` JSON array nests it into a one-element array when the caller wraps the call in `@()` (HIGH).
- **Added the missing template skills** `add-practice`, `apply-practice`, and `ux-review` (with its `.claude/references/ux-laws.md` reference) from `claude-code-bootstrap`, completing the canonical skill set. The bodies are the current canonical versions (custom `explorer` agent, normalized `model:`/`effort:` frontmatter; the KB-write skills use `.claude/scripts/kb-upsert.sh`).
- **New `agy-execute-plan` Claude Code skill** ("execute plan with antigravity"): hands an existing plan to the Antigravity CLI (`agy`) to implement end-to-end, then independently verifies the result against the plan via the test suite and git diff (never AGY's self-reported log), fixes whatever AGY left incomplete or broke, and reports an honest blocked/partial/complete status. Encodes the verified agy v1.0.8 operating details: run headless with empty stdin + `--dangerously-skip-permissions` or it hangs, redirected stdout is empty so judge by diff and tests, plus the Windows PATH reload and the `AGY_BLOCKED.md` halt signal.
- New Prisma technology in the KB with its first gotcha (HIGH): an index created via raw SQL in a migration but not declared in schema.prisma is treated as drift, and every later `prisma migrate dev` silently emits `DROP INDEX` into unrelated migrations. Declare the index with `@@index(..., type: Gin, map: "name")` so Prisma owns it, and restore an already-shipped drop with a follow-up `CREATE INDEX IF NOT EXISTS` migration.
- **New `merge-worktrees` Claude Code skill** ("merge worktrees"): merges every open git worktree and local branch into the main branch, pushes, then removes the worktrees and force-deletes the merged branches (locally and, with confirmation, on the remote). It detects the real main branch, confirms a plan before any merge, commits pending worktree work first, merges with `--no-ff`, and treats merge conflicts and non-fast-forward pulls as hard stops; nothing is deleted until the merge is committed and pushed.

### Changed
- **The master `llms.txt` is a router again: 55 KB -> 10 KB (81% smaller).** Its 83 shelf pointers had grown into multi-paragraph summaries (median 310 B, worst 3.7 KB for Postgres alone) that enumerated the gotchas instead of pointing at them, duplicating content one level down and costing ~13k tokens of always-on context in every session that follows RULE 1. Each line is now one clause naming the technology and its scope; the specific gotchas live on the shelf, which is where the two-level design always intended them. No shelf lost its pointer and no entry was deleted.
- **`scripts/check-index-counts.mjs` no longer miscounts cross-shelf pointers.** `kb/hono/llms.txt` carries a deliberate pointer to `../web-security/` annotated "Not counted as a Hono entry"; the reconciler counted it and demanded a 2 that the master index was right to call 1. Bullets whose link target leaves the folder are now excluded.
- Normalized eight entries onto the documented `tech:`/`tags:`/`severity:` frontmatter: three NinjaOne entries gained `tech:` and moved their `title:` into a body H1, `kb/tailwind/v4-workspace-resolution.md` had `tech: tailwind-css` against folder `kb/tailwind`, three `kb/teams-sharepoint/` entries claimed `tech: graph-api` (now a tag instead), and `kb/better-auth/organization-plugin-no-hierarchy.md` had no `tags:` and a stray BP-schema `applies-to:`. Uppercase `severity: HIGH` values were lowercased to match the legend.
- Repointed LL-G and BP knowledge-base references from the `wellforce-brandon` GitHub org to `BoardPandas` after both repos moved (fetch URLs, `gh api` paths, and raw content links)
- **Synced `.claude/references/hooks-and-settings.md` to Claude Code 2.1.201** from the claude-code-bootstrap template: hook structured output (updatedToolOutput, additionalContext, reloadSkills/sessionTitle), Tool(param:value) parameter matching, HTTP hook custom headers with env-var interpolation, the PermissionRequest auto-approval pattern, new settings (defaultMode rename, fallbackModel, enforceAvailableModels, disableBundledSkills, requiresMinimumVersion), the full six-tier settings precedence chain, and the ENABLE_PROMPT_CACHING_1H cache lever.
