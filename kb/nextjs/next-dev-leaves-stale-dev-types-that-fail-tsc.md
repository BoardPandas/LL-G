# `next dev` leaves `.next/dev/types` behind, and `tsc` then fails on routes you have since moved or deleted

## PROBLEM
Running `next dev` writes route type validators under `.next/dev/types/`
(for example `validator.ts`, which imports every `page.tsx` it saw). A
`tsconfig.json` generated by Next includes that folder:

```json
"include": ["next-env.d.ts", "src/**/*.ts", "src/**/*.tsx", ".next/types/**/*.ts", ".next/dev/types/**/*.ts"]
```

The files are not regenerated when you stop the server. Move or delete a route
afterwards and the next `tsc --noEmit` fails inside generated code:

```
.next/dev/types/validator.ts(1622,39): error TS2307: Cannot find module
  '../../../src/app/(dashboard)/settings/deleted-tickets/page.js'
```

The error names a file you did not write, in a directory that is git-ignored,
about a route that no longer exists, so it reads like a broken build rather
than stale output. CI is unaffected because it never ran the dev server, which
makes it look like a local-only mystery.

## WRONG
```bash
next dev -p 3917 &          # quick check of a redirect
# ...stop it, then git mv a page...
pnpm run type-check         # fails in .next/dev/types/validator.ts
```

## RIGHT
```bash
# After any throwaway dev-server run, remove what it generated before type-checking.
rm -rf .next/dev
git checkout -- next-env.d.ts     # next dev also rewrites this
pnpm run type-check
```

## NOTES
- `next dev` may also create other untracked files in the app directory (an
  `AGENTS.md` when agent rules are enabled). Check `git status` after a
  throwaway run.
- Starting the dev server again regenerates the validators and also clears the
  error, which is why this is easy to "fix" by accident and not understand.
